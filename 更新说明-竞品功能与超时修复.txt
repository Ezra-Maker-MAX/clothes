一、先说首页报警的根因（重要）
═══════════════════════════════════════════
你截图里的 TimeoutException 30s 不是客户端问题，是服务端：
推荐接口每个请求（包括首次打开）都会先实时调「和风天气」API，
但这个调用没有超时保护——天气接口一挂起，整个函数被拖满 30 秒
被 Vercel 强制掐断，客户端就看到 30s 超时。

修复：天气调用加 4 秒超时，拿不到自动降级（不影响推荐主链路）。
修好后整条生成链 ≈ 天气4s + AI润色8s + 数据库2s，客户端 30s 稳够。

※ 这也解释了之前的天气疑点：天气卡一直显示 24°C/多云（兜底值），
  很可能和风 API 的 key/网络一直没成功。推送后观察：若天气卡变了，
  说明修通了；若还是 24/多云，去 Vercel 检查 WEATHER_API_KEY 变量名
  和值，改完必须重新 Deploy。

二、按你发的竞品截图复制的功能（UI 保持衣念莫兰迪紫风）
═══════════════════════════════════════════
1. 单品详情页（对应竞品「单品详情」大图页）
   - 衣橱网格/列表里点任意单品 → 详情页：
     大色块图卡 + 名称 + 状态/分类/颜色/品牌/穿着次数/最近穿着
   - 「穿过它的时候」：这件单品参与过的搭配记录
   - 底部「编辑」：改名/改分类/改颜色/改品牌（服务端新增 PATCH）
   - 底部「删除」：二次确认后软删（历史记录不断链）

2. 衣橱页升级（对应竞品右上角工具钮 + 列表视图）
   - 右上角「⋮」菜单：网格/列表视图切换；
     排序：按最近添加 / 按最常穿 / 按最近穿着
   - 列表视图：行卡显示 品牌 · 颜色 + 「穿过 N 次/没穿过」徽章
   - 头部「+」快捷添加；添加表单新增「品牌」可选字段

3. 搭配页接真实数据 + DIY 搭配（对应竞品搭配页 + DIY）
   - 双列拼图卡显示你真实的历史搭配（单品 emoji 组合 + 场合 + 日期）
   - 右下角悬浮「+」→ DIY 搭配选品器：
     上衣/下装(含裙装)/鞋子 各选一件 → 「存为我的搭配」
   - DIY 的套带「DIY」角标，和 AI 推荐区分（服务端支持 manual 来源）

═══════════════════════════════════════════
三、这期没抄的功能（说明原因）
═══════════════════════════════════════════
- 编辑分类（拖拽排序/自定义分类）：推荐引擎按固定 6 类计算适配度，
  动态分类会让引擎"失明"。列入后续：分类数据表化 + 引擎适配。
- 价格/单次穿着成本：数据库没有价格字段，需要加列+录入流程。
- AI 美化/换图（图片相关）：依赖图片上传链路，属下一阶段。
- 社区/圈子（关注/投票/OOTD 分享）：需要社区后端，超出当前架构。

四、怎么用
═══════════════════════════════════════════
1. PowerShell 解压到位（-Force 覆盖，不会产生嵌套目录）：
   Expand-Archive -Path "<zip路径>\yinian-competitor-bundle.zip" -DestinationPath "C:\Users\lenovo\Desktop\dapei-app-push-bundle\dapei-app" -Force

2. 推送：
     git add -A
     git status --short     ← 应该刷出一大屏（没变化就是没解压对）
     git commit -m "feat: 单品详情/衣橱视图排序/DIY搭配；fix: 天气调用超时"
     git push

3. 验证（等 Vercel 部署完，清缓存强刷网页）：
   a) 首页不再 30s 超时（天气挂了也会 4s 内降级出推荐）
   b) 衣橱：点单品进详情 → 编辑改名 → 列表里变了；删除一件 → 少一件
   c) 右上角 ⋮：切列表视图、换排序
   d) 搭配页：显示真实历史套数；右下 + → DIY 配一套 → 卡片带 DIY 角标

4. APK 生效：git tag v0.1.5 && git push origin v0.1.5
   （v0.1.4 若已打包可跳过直接 v0.1.5；手机先卸载旧版再装）
