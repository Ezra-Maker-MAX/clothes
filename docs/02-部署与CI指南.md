# 02 · 部署与 CI 指南（Vercel 自动部署 + GitHub Actions 打 APK）

## 一、整体部署拓扑

```
git push (main)
   │
   ├──▶ Vercel Git 集成（零配置）────────▶ 自动构建 Web 端 + API → *.vercel.app
   │
   └──▶ git tag v0.1.0 / 手动触发 ────▶ GitHub Actions → Flutter APK 产物
```

## 二、Vercel 绑定 GitHub（一次性，5 分钟）

1. 代码推上 GitHub：`git init && git add . && git commit -m "init" && git push`
2. 登录 [vercel.com](https://vercel.com) → **Add New Project → Import** 选该仓库
3. Framework Preset 选 **Other**（本项目是纯 serverless 函数，无需构建命令）
4. 先点 Deploy 部署一次（此时无环境变量，`/api/health` 会走 mock 模式——这是预期行为）
5. **Settings → Environment Variables** 添加（关键步骤）：

| 变量 | 来源 | 必填 |
|---|---|---|
| `TURSO_URL` | `turso db show dapei --url` | ✅ |
| `TURSO_AUTH_TOKEN` | `turso db tokens create dapei` | ✅ |
| `BLOB_STORE_ID` | Storage → Create Blob Store(access=Public) → Connect，**自动注入** | 上传功能需要 |
| `BLOB_READ_WRITE_TOKEN` | 仅代码在 Vercel 外运行时才手写，通常留空 | 否 |
| `WEATHER_API_KEY` | 和风天气 / OpenWeather 后台 | 可选（不配也有真天气） |

6. 重新 **Deployments → Redeploy**，之后每次 `git push` 自动部署

> ⚠️ 环境变量永远不要写进代码或提交到 git，本地用 `.env`（已进 .gitignore）。

## 三、Turso 建库与初始化

## 五、Android APK 工作流

文件：`.github/workflows/android-build.yml`（第二阶段 `app/` Flutter 代码就位后生效）

- **手动**：仓库页 → Actions → Build Android APK → Run workflow
- **打 tag 正式包**：`git tag v0.1.0 && git push --tags`
- 产物在 Actions 运行页底部 Artifacts 下载 `dapei-apk`

## 六、Flutter Web 端部署思路（第三阶段）

两选一：

1. **简单**：GitHub Actions 里 `flutter build web` → 产物推到 `build-web` 分支 → Vercel 监听该分支部署静态页（API 走 main 分支）
2. **一体**：`.github/workflows/vercel-deploy.yml` 扩展——build web 输出到 `public/`，用 Vercel CLI `--prebuilt` 一次部署函数 + 静态页

方案 2 的骨架已在 `vercel-deploy.yml` 中预留，需要配 `VERCEL_TOKEN` / `VERCEL_ORG_ID` / `VERCEL_PROJECT_ID` 三个 Secrets。

## 七、Vercel Blob 配置（衣橱图片上传，5 分钟）

### 7.1 为什么需要它

衣橱单品图、历史记录里的搭配图都要一个**能直接显示的公开 URL**。Vercel Blob 上传一行`put()` 就返回一个 CDN 直链，省掉 Cloudinary / S3 + 签名 URL 那一整套。Hobby 计划有免费额度，够私人使用。

### 7.2 创建 Store（三步，别选错 access）

1. Vercel 面板 → 你的项目 →顶栏 **Storage** 标签
2. **Create Database** → 选 **Blob** → Continue
3. 弹窗里两个必填项：
   - **Store Name**：随意，建议 `wardrobe`
   - **Access**：⚠️ **必须选 Public** —— 创建后不可更改，改不了就只能删了重建
4. 选 **Region**：挑离你最近的，国内用建议 `Singapore (sin1)` 或 `Tokyo (hktok1)` 之类

因为是在项目内创建的，Vercel 会**自动 Connect to Project**，这一步不需要你手动操作。

### 7.3 认证：两种模式，认哪种都可能出岔子

| 模式 | 何时用 | 你要做什么 |
|---|---|---|
| **OIDC**（官方推荐） | 代码跑在 Vercel 上（本项目就是） | **什么都不用做**，Vercel 自动注入 `BLOB_STORE_ID` + OIDC 凭证 |
| **长效 token** | 代码跑在 Vercel 之外（本地脚本、CI、浏览器直传） | Store → Tokens → **Create Token** → 勾 Public Access → 得到 `vercel_blob_rw_…` |

> ⚠️ **易踩的坑**：OIDC 模式下 `BLOB_READ_WRITE_TOKEN` **是空的**。
> 如果自检代码只认这个变量，就会出现「上传其实成功了，但提示说没配置 Blob」的假警报。
> 本项目 `server/lib/blob.ts` 的 `blobConfigured()` 两种都认，`/api/health` 会显示 `authMode` 字段告诉你是哪种（`oidc` / `token`）。

### 7.4 验证（浏览器直接打开）

```
https://selena.ccwu.cc/api/health          # 看 blob.ready / blob.authMode / blob.detail
https://selena.ccwu.cc/api/upload          # 同上，另含抠图服务状态
```

- `ready: true` 且 `detail` 含「实测list 成功」→ 一切正常
- `ready: false` 且 `detail` 提示未配置→ 回7.2 重新确认 access 是否选了 Public、是否 Connect 到项目
- `ready: false` 且 detail 提到 **suspend / blocked / 403** → store 被 Vercel 封停，**代码侧无解**，只能提 [Vercel Support 工单](https://vercel.com/support)

真实上传测试：

```bash
# 生成一张 1x1 的 PNG（约 70 字节）
curl -X POST https://selena.ccwu.cc/api/upload \
  -H 'Content-Type: application/json' \
  -d '{"filename":"t.png","contentType":"image/png","dataBase64":"iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAYAAAAfFcSJAAAADUlEQVR42mP8z8BQDwAEhQGAhKmMIQAAAABJRU5ErkJggg=="}'
```

返回里的 `url` 就是 CDN 直链，粘浏览器能打开就算成功。

### 7.5 Hobby 免费额度与封停风险

官方 pricing 页当前列的 Hobby 含额度（**随套餐可能调整，以面板 Storage → Store 详情为准**）：

| 项目 | Hobby 含额度 |
|---|---|
| 存储 | 1 GB / 月 |
| Simple Operations（按 URL 读取，cache MISS） | 前 10,000 次 |
| Advanced Operations（`put()` / `copy()` / `list()`） | 前 2,000 次 |
| 数据传输 | 前 10 GB |

**注意**：`put()` 算 Advanced Operation，所以每上传一张图扣一次。私人使用几千张完全够。

**关键风险**：Hobby 一旦某项超限，**Vercel 会直接封停 store**，表现为 `put()` / `list()` 全部 403 `"store has been suspended"`，图片 URL 也变成打不开。官方说明是「等 30 天恢复，或升级 Pro 解锁」。所以：
- 衣橱图片压缩后再传（App 已强制压到 3MB 以内，1GB 能放 300+ 张）
- 偶尔看一眼 Storage → Store 详情的用量
- 面板会发接近上限的邮件提醒

### 7.6 抠图（可选，不配也能用）

`POST /api/upload` 里已经留好挂载点，配了就把透明 PNG 也一起落 Blob，**任何失败都静默降级为原图**，绝不阻断上传：

| 变量 | 来源 |
|---|---|
| `REMBG_API_URL` | 自部署 rembg 服务端点（POST 二进制 → 返回透明 PNG），优先用这个，省第三方额度 |
| `REMOVE_BG_API_KEY` | [remove.bg](https://www.remove.bg/dashboard#api-key) 官方 Key |

两个都配时优先 `REMBG_API_URL`。
