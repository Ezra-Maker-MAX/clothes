# 03 · 图片存储方案（Vercel Blob 起步，Cloudinary 预留）

> 原则：Turso 只存 URL，图片本体放对象存储。

## 一、两个方案对比

| 维度 | Vercel Blob ✅ 首选 | Cloudinary |
|---|---|---|
| 接入成本 | 零配置，Vercel 面板一键连接，token 自动注入 | 需注册 + 配置 cloud_name/api_key/secret |
| SDK | `@vercel/blob` 一行上传 | SDK 稍重，签名上传流程 |
| 免费额度 | Hobby 版 1GB 存储 + 10GB 流量/月 | 25 credits/月（约 25GB 转换） |
| 图片处理 | 无（裁剪/压缩需自己做或用占位参数） | 强：URL 即裁剪、格式转换、质量压缩 |
| 抠图能力 | 无 | remove.bg 类效果可搭配第三方 |
| 计费风险 | 与 Vercel 同账单，超量降级清晰 | 独立平台，超额需单独处理 |

**结论**：起步阶段单品图片量小、需求只是"存 + 展示"，Vercel Blob 零配置最快跑通；
等接入 AI 抠图/自动裁剪时，Cloudinary 的 URL 处理能力才开始有优势。

## 二、上传链路（当前实现）

```
Flutter 拍照/选图
   │  base64 编码
   ▼
POST /api/upload  { filename, contentType, dataBase64 }
   │  @vercel/blob put() → Blob 存储
   ▼
返回 { url }
   │
   ▼
POST /api/wardrobe { imageUrl: url, ... }   → Turso 只存这个 URL
```

- 客户端缓存 `url`，首页三图直接 `<Image.network(url)>`
- 软删单品不删 Blob 文件（历史记录还要回显），存储超量时再做 GC
- 上传限 8MB，Flutter 端建议压缩到长边 1280px 再传

## 三、抠图 API 挂载点（已预留）

`api/upload.ts` 返回前预留了处理位：

```ts
// blob.url → 第三方抠图 API → 回写 thumbnail_url
```

第二阶段接入时：上传成功后异步调抠图服务，把带透明背景的图存为
`thumbnail_url`，主图保持原图。候选服务：remove.bg、PhotoRoom API、
阿里云视觉智能（国内速度优）。

## 四、迁移到 Cloudinary 的退路

`wardrobe_items.image_url` 是纯 URL，不绑定存储商。若后续切换：

1. 写一次性迁移脚本：拉 Blob URL 列表 → 下载 → 传 Cloudinary → UPDATE 回表
2. Flutter 端零改动（URL 对它黑盒）

这就是"URL 解耦存储"的意义——随时搬家，数据不疼。
