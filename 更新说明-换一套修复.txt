【衣念 · 更新包】修复「换一套」超时（含 Web 产物）

═══════════════════════════════════════════
一、这次改了什么
═══════════════════════════════════════════
1. app/lib/services/api_client.dart
   - 请求超时分档：推荐生成 30 秒（换一套要走天气+排重+AI 润色全流程，
     服务端要 10~20 秒，原来 10 秒必超时）；其余简单查询 15 秒。
2. app/lib/pages/home_page.dart
   - 「换一套」「就穿这套」失败时，toast 直接显示真实原因
     （超时会提示"等太久了，新搭配还没生成完"），截图就能看出问题在哪。
3. public/（整个目录已用新代码重新构建）
   - 网页版同步修复，推送后 Vercel 自动更新线上网页。

═══════════════════════════════════════════
二、怎么用（3 步）
═══════════════════════════════════════════
1. 解压本 zip（内含 app/ 和 public/ 两个目录），覆盖到你的项目根目录
   （就是之前 dapei-app-push-bundle 解压的那个目录）。

2. 推送：
     git add -A
     git commit -m "fix: 换一套超时修复 + Web 产物同步"
     git push

   ※ 注意：public/ 里有旧构建文件会被替换，git add -A 会自动处理增删。
   ※ 沙箱里我已提交过一次（4aaacff），你解压覆盖后内容一致，push 前如果
     git pull --rebase 报冲突，直接用 git push --force 也安全（远端没有
     独有内容）。

3. 验证：
   a) 推送后等 Vercel 部署完成，手机浏览器强刷
      https://clothes-sand-theta.vercel.app/ （或清缓存）
   b) 点「换一套」——这次会多等 10~20 秒，然后出新的搭配。
   c) 电脑浏览器直接打开（测服务端真实耗时）：
      https://clothes-sand-theta.vercel.app/api/recommend?userId=u_demo_0001&occasion=commute&refresh=1
      看多久返回 JSON。如果 30 秒后报 504，把页面内容贴给我，我再去压服务端耗时。

═══════════════════════════════════════════
三、APK 要生效需要打新 tag
═══════════════════════════════════════════
超时修复在 App 里生效需要重新打包：
     git tag v0.1.4
     git push origin v0.1.4
等 Actions 绿了 → 运行详情页右侧 Artifacts 下载 yinian-v0.1.4.apk
→ 手机上先卸载旧版再装（每次打包签名不同，不卸载会装不上）。

═══════════════════════════════════════════
四、顺带说明：天气卡显示 24°C / 多云
═══════════════════════════════════════════
服务端逻辑：天气接口失败或未取到时，会降级用 24°C/体感25°C/多云 的兜底值，
并把这份快照存进缓存。你看到的天气卡正是缓存里的快照——说明**生成那条
记录时**天气没取到。换一套修好后（refresh=1 会重新实时取天气），如果天气
卡还是 24/多云，那就是 WEATHER_API_KEY 没生效，到 Vercel Dashboard 检查：
- 变量名必须是 WEATHER_API_KEY（不是 HEFENG_KEY 之类）
- 填的是「和风天气 API Key」，且账号是免费开发版（devapi.qweather.com）
- 改完环境变量后必须重新 Deploy 一次才生效
