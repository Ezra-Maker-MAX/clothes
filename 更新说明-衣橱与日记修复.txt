【衣念 · 更新包】衣橱「添加单品」上线 + 穿搭日记日期修复（含换一套超时修复，若上一个包还没推，本包已全部包含）

═══════════════════════════════════════════
一、这次改了什么
═══════════════════════════════════════════
1. 衣橱页整体接入真实数据（之前是写死的演示数据！）
   - 列表、分类 tab 计数、头部统计（X 件单品 · Y 件还没上过身）
     全部来自云端 /api/wardrobe。
   - 「添加单品」按钮和网格末尾的虚线「+」格现在都能点了：
     弹出表单（名称 + 分类 + 颜色可选）→ 存进云端衣橱，
     保存成功自动刷新列表。添加的单品立即参与「换一套」搭配池。
   - 拍照上传/自动抠图是下一阶段（表单底部有说明），先手动记名字。

2. 穿搭日记日期修复
   - 日历只点亮当前月份的记录（之前 9 月的记录会错亮到 10 月网格）。
   - 时间线强制按日期新→旧排列（双保险，不依赖服务端）。
   - 日期格式化健壮化：兼容带时间的日期串，不再出现乱码日期；
     月/日去掉前导零（"10月02日"→"10月2日"）。
   - 时间线 emoji 按场合变化（通勤👔 约会💄 面试💼 聚会🥂 日常🌿），
     不再全是👗。
   - 服务端评分兜底 0→5 星：之前「就穿这套」没评分，时间线显示
     5 颗空心星很难看，现在默认 5 星。

3. 换一套超时修复（上个包的内容，若未推送本包自动包含）
   - 请求超时分档：生成 30 秒 / 查询 15 秒。
   - 失败 toast 显示真实原因。

═══════════════════════════════════════════
二、怎么用（3 步）
═══════════════════════════════════════════
1. 解压本 zip，覆盖到项目根目录（dapei-app-push-bundle 那个目录）。

2. 推送：
     git add -A
     git commit -m "feat: 衣橱真实数据+添加单品；fix: 穿搭日记日期"
     git push

   ※ 沙箱里我已提交同内容（见下方 git log），若 push 报冲突，
     git push --force 是安全的（远端无独有内容）。

3. 验证（网页版，推送后等 Vercel 部署完，清缓存强刷）：
   a) 衣橱页：应显示 10 件演示单品（库内真实数量），
      分类计数、头部统计都是真的。
   b) 点「添加单品」→ 填名字选分类 → 挂进衣橱 → 列表立即多一件。
   c) 回首页点「换一套」：新添加的单品有机会被翻牌。
   d) 穿搭日记：时间线按日期新→旧；日历只亮 10 月的日子。
